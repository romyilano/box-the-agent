# Page 4 — Not One Master Key, But Many Small Ones

**Narrative purpose:** Scopes. A token carries named permissions; every tool demands a specific scope *and* a minimum tier. Fine-grained, least-privilege — not one skeleton key.

**Scene:**

Close on **ARC's** orbiting token-badge, which unfolds into a **key-ring**. Each key is small and etched with exactly one verb-phrase: `membership:read`, `events:rsvp`, `headsets:lend`, `research:query`, `agent:inbox:write`. The keys are distinct shapes, clearly not interchangeable.

**Romy** holds up a single tool on the floor — say the headset shelf — and it has a **lock** that only accepts the `headsets:lend` key *and* checks the ring you're standing on. A key that doesn't match simply won't turn; the lock shows a small `needs_scope` tag.

**Dialogue:**
- **ARC:** "My badge isn't one master key. It's a ring of small keys, each etched with a single permission."
- **Romy:** "Exactly. `events:rsvp` lets you RSVP me to things. `headsets:lend` lets you borrow a headset. Each tool checks for *its* key — and for the ring you're standing on."
- **ARC:** "So reaching a tool needs two things at once: the right scope, and a high-enough tier."
- **Romy:** "And here's the sharp edge — you can't bolt a new key onto an existing badge. If you need a scope you don't have, we mint a *fresh* badge that includes it from the start. No quiet privilege creep."

**Caption (bottom):** *A scope is one etched verb. Every tool demands a specific scope and a minimum tier. New scopes never graft onto an old token — you mint a new one, on purpose.*
