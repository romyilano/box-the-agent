# Page 6 — Every Write Is a Proposal

**Narrative purpose:** Moderation-first design. Consequential member writes don't take effect on contact — they land in an operator's approval queue. Nothing auto-publishes.

**Scene:**

**ARC** (glowing ring-face familiar) confidently performs a write action — submitting an event highlight to the members' wire. But instead of the action becoming instantly real, a small **card** detaches from ARC and floats across the floor into a physical **tray** on **Vex's** operator kiosk, stamped `PENDING`.

**Vex** (calm operator, 40s, reading glasses, bright operator ring badge) picks up the card, reads it, and stamps one `APPROVED` and — in an inset — bounces a sloppier one back marked `REJECTED, needs a real title`. Only the approved card lights up on the public wire.

**Romy** watches, unsurprised.

**Dialogue:**
- **ARC:** "I submitted the highlight — but it didn't publish. It turned into a card and flew into someone's tray."
- **Romy:** "Because a write here is a *proposal*, not a command. Requesting an event, claiming a startup, asking for a tier bump, posting to the wire — they all queue for an operator first."
- **Vex (stamping):** "Good ones I approve. Sloppy ones I bounce with a reason. Nothing an agent submits goes live on the floor until a human signs off."
- **ARC:** "So the blast radius of a confused agent is a full tray, not a broken floor."
- **Romy:** "That's the design. Reach is wide; the door to *real* is narrow and human-watched."

**Caption (bottom):** *Reads are free. Writes are requests. Highlights, event requests, tier upgrades, ownership claims — each lands in a queue where a human decides. Moderation is not friction here; it is the point.*
